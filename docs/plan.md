# Samplette — план

Десктопный менеджер семплов: «разобрал библиотеку → почистил → выгрузил в DAW или на железо» в одном приложении.

## Позиционирование

На рынке менеджеры (XO, Sononym, ADSR Sample Manager, Loopcloud, Splice) не редактируют файлы, а редакторы (Audacity, RX) не управляют библиотекой. Ставка Samplette — на три пробела:

1. **Библиотека + встроенный аудиоредактор, пакетная обработка и стем-сепаратор** — обрезка, нарезка, фейды, нормализация, конвертация, разделение треков на стемы и сохранение фрагментов как семплов.
2. **Экспорт китов под железо** — Digitakt, SP-404, MPC, Polyend, M8 одной кнопкой.
3. **Локальный поиск похожих и поиск текстом** для любых звуков, офлайн, без подписки.

Плюс принципы: метаданные не заперты в проприетарной базе, быстрая работа на 100k+ файлов.

## Стек

| Слой | Выбор | Почему |
|---|---|---|
| Оболочка | Tauri 2 | Маленький бинарник, Rust для тяжёлого аудио, нативные диалоги и drag-out |
| UI | Vue 3 + Vite + TypeScript, Pinia, shadcn-vue, UnoCSS | Привычный стек |
| Данные | SQLite (rusqlite на стороне Rust), FTS5 для поиска | Один файл, быстро, полнотекстовый поиск из коробки |
| Декодирование | symphonia | WAV/AIFF/FLAC/MP3/OGG на чистом Rust |
| Запись / ресемплинг | hound, rubato | WAV-запись, качественный SRC |
| Воспроизведение | cpal (Rust) или Web Audio в webview | Низкая задержка превью |
| Time-stretch для превью | signalsmith-stretch (MIT) | Rubber Band — GPL/коммерческая лицензия |
| Анализ (BPM, тональность) | stratum-dsp (+ beat-this для бит-трекинга) | MIT/Apache; aubio (GPL) и Essentia (AGPL) не подходят |
| Эмбеддинги | Аудио-энкодер CLAP (laion/clap-htsat-unfused, int8 ONNX, 34 МБ, Apache-2.0) через ONNX Runtime (`ort`) | Категории и поиск похожих одной моделью; векторы категорий посчитаны заранее, текстовый энкодер в приложении не нужен |
| Векторный поиск | sqlite-vec, при нехватке скорости — usearch | Без отдельного сервера |
| Отпечатки (дубликаты) | rusty-chromaprint (MIT) | Чистый Rust, без LGPL-части оригинала |
| Стем-сепарация | ONNX Runtime + подключаемые модели (Spleeter по умолчанию) | См. риски по весам моделей |
| Waveform и редактор | wavesurfer.js (BSD-3) на старте → свой canvas/WebGL-рендер с пиками из Rust | peaks.js — LGPL |
| Drag в DAW | tauri-plugin-drag | Перетаскивание файлов из приложения наружу |

Полный список с лицензиями — [dependencies.md](dependencies.md).

## Этапы

### Этап 0 — Каркас
- Tauri + Vue проект, CI-сборка под macOS (потом Windows).
- Добавление папок-источников, рекурсивный скан, запись в SQLite.
- Список файлов с виртуальным скроллом, базовые метаданные (длительность, sample rate, битность, каналы).
- Превью по клику / стрелкам, waveform (пики считаются в Rust и кешируются).
- Drag-and-drop файла в DAW.

**Готово, когда:** библиотека на 50k файлов сканируется, листается без лагов, звук играет мгновенно.

**Статус (2026-10-23):** реализовано всё, кроме CI. Скан 20k WAV — 1,2 с, повторный — 0,1 с. Папки пересканируются инкрементально при запуске. Для WAV с кодеками, которые не открывает symphonia (Ogg-in-WAV, часть ADPCM), метаданные читаются из RIFF-заголовка, но воспроизведение и waveform для них пока не работают.

### Этап 1 — MVP-библиотека
- Теги, избранное, коллекции (виртуальные папки), рейтинг.
- Поиск: FTS по имени/пути/тегам + фильтры по метаданным.
- Инкрементальный пересканирование и слежение за папками (`notify`).
- Обработка переездов/переименований файлов без потери тегов (по хешу).
- Экспорт/импорт тегов в sidecar-файл (JSON) — защита от vendor lock-in.

**Это MVP** — уже можно отдавать первым пользователям.

**Статус (2026-10-23):** готовы полнотекстовый поиск FTS5 (по имени, папкам и тегам, по началу слова, без учёта диакритики), теги, избранное, множественное выделение и drag нескольких файлов. Готовы слежение за папками (notify, пересканирование через 0,8 с тишины) и сохранение тегов и избранного при переименовании, переносе между папками и повторном добавлении источника (по отпечатку содержимого, данные удалённых файлов хранятся 90 дней). Готовы коллекции (контекстное меню строки, раздел в боковой панели, членство переживает переносы файлов) и экспорт и импорт избранного, тегов и коллекций в JSON (слияние, поиск файла по пути, затем по отпечатку). Этап 1 закрыт.

### Этап 2 — Анализ
- Фоновая очередь анализа с прогрессом, не блокирующая UI.
- BPM, тональность, громкость (LUFS), определение one-shot / loop.
- Автокатегория (kick, snare, hat, bass, vocal, pad…): сначала по имени файла и папкам, для остальных — по аудио-энкодеру CLAP (сравнение с заранее посчитанными векторами категорий). Тональность по звуку — только для тональных категорий.
- Превью в темпе и тональности, заданных пользователем. **Готово (2026-10-23):** кнопка Sync в плеере (темп и тональность проекта хранятся в settings.json); лупы с известным BPM растягиваются к темпу проекта (с выбором половинного/двойного темпа, не более ×2), сэмплы с известной тональностью транспонируются к ней (кратчайший интервал, параллельные мажор/минор считаются одной тональностью); рендер signalsmith-stretch перед воспроизведением: 4-секундный луп — ~45 мс, файлы длиннее 60 с играют без изменений.

**Статус (2026-10-23):** готовы фоновая очередь (половина ядер, сначала видимые и выбранные семплы, пауза), громкость (пик, LUFS), one-shot / loop / long (по имени, длине, числу атак и огибающей) и BPM: из имени, для коротких лупов — по длине с выбором октавы детектором stratum-dsp (78% точно на 124 лупах без подсказки в имени), для длинных — детектором по 30-секундному окну. Вся библиотека (32k) анализируется за несколько минут.

**Категории (2026-10-23):** 17 категорий. Сначала по имени файла и папкам (82% реальной библиотеки, первое по положению ключевое слово, папки с общими барабанными словами не учитываются). Для остальных — по аудио-энкодеру CLAP (34 МБ, скачивается кнопкой, проверка SHA-256): 10 ближайших подписанных соседей из той же библиотеки, порог согласия 0,6 (~83% точности на половине неподписанных); при < 200 подписанных — заранее посчитанные текстовые прототипы. Тональность по звуку — только для тональных категорий (бас, синт, пэд, клавиши, гитара, струнные, духовые, вокал) и не для one-shot. Векторы сохраняются в базе для будущего поиска похожих; вся библиотека — около 27 минут в фоне.

### Этап 3 — Аудиоредактор и пакетная обработка
**Встроенный редактор** (клавиша E, кнопка в плеере или пункт меню) — в отдельном окне на каждый файл, можно держать открытыми несколько. **Основа готова (2026-10-23):** waveform с зумом и прокруткой, выделение, курсор, воспроизведение выделения с петлёй; crop, delete, silence, fade in/out (3 кривые), gain ±3 dB, normalize (−0.3 dB), reverse; бесконечный undo/redo (правки — список поверх исходника); сохранение в новый WAV рядом или поверх WAV с копией в папке backups. **Сетка и привязка (2026-10-24):** сетка тактов и долей по BPM сэмпла (поле BPM правится, 4/4, «первый такт от курсора», без BPM — сетка по времени), привязка курсора и выделения к сетке (магнит, S) и к нулям сведённого сигнала в пределах 10 мс (меню «Вид»); ⌥ при перетаскивании инвертирует обе. **Точки лупа (2026-10-24):** из выделения (⇧L), правка в общем списке (undo, сдвиг при crop/delete); читаются из `smpl`-чанка WAV при открытии и пишутся в него при сохранении (одна прямая петля, unity note C4); полоса на линейке, клик по ней выделяет луп. Осталось из списка ниже: нарезка, pitch/time-stretch выделения, спектрограмма, cut/copy/paste.
- Waveform с зумом до сэмпла, выделение регионов, курсор, лупинг выделения при прослушивании.
- Операции: cut / copy / paste / delete / crop, тишина, fade in/out (с выбором кривой), gain, normalize (peak / LUFS), reverse, DC offset.
- Снап к zero-crossing, точки лупа (запись `smpl`-чанка в WAV для семплеров).
- Нарезка: по транзиентам, по сетке BPM, по тишине → экспорт слайсов как новых семплов в библиотеку.
- Pitch / time-stretch выделения (signalsmith-stretch).
- Вид спектрограммы.
- **Готово (2026-10-23): настраиваемая волна** (Settings → Waveform): пики / пики + RMS / столбики, линейная шкала или dB, каналы раздельно или смешанно, цвет по частотам (низ — красный, середина — зелёный, верх — синий); на глубоком зуме — кривая с точками отсчётов; ⌥-прокрутка — вертикальный зум; мини-карта всего файла над волной (видимый участок рамкой, перетаскивание, колесо — зум, двойной клик — показать всё). В плеере всё то же: волна строится из потокового обзора файла (пик, RMS, полосы по блокам, кэш последних 8 файлов в памяти); путь к файлу — внизу, сокращённый, клик открывает Finder.
- Неразрушающая модель: список правок (edit list) поверх исходника, многоуровневый undo/redo, рендер при сохранении — новый файл или замена с бэкапом.

**Пакетная обработка** над выделением в библиотеке:
- Обрезка тишины, нормализация, фейды, конвертация формата/SR/битности, моно↔стерео.
- Переименование по шаблону (`{category}_{bpm}_{key}_{n}`).
- Пресеты цепочек операций.

### Этап 3.5 — Стем-сепаратор
- Разделение трека на стемы: 2 (вокал / минус), 4 (вокал, барабаны, бас, остальное), 5 (+ пианино).
- Инференс локально через ONNX Runtime, на macOS — CoreML (Apple Silicon); фоновая очередь с прогрессом и отменой.
- Модели — подключаемые, скачиваются по требованию; по умолчанию Spleeter (MIT), опционально Mel-RoFormer для вокала после юр. проверки.
- Мультитрековый просмотр стемов с mute/solo, прослушивание, экспорт стема или выделенного фрагмента прямо в библиотеку (с автотегами `stem:vocals` и т. п.).
- Связка с редактором: открыть стем → вырезать фразу → сохранить как семпл.

### Этап 4 — Экспорт под железо
- Профили устройств: формат, SR, битность, моно/стерео, макс. длина имени, структура папок, лимиты.
- Сборка кита из коллекции → проверка → экспорт на диск/карту.
- Старт с 2–3 популярных устройств (Digitakt, SP-404 MkII, M8), дальше по запросам.

### Этап 5 — Умный поиск
- «Найти похожие» по эмбеддингам для любого семпла. **Готово (2026-10-23):** пункт меню и клавиша S, перебор всех векторов в памяти (миллисекунды на 32k), 500 ближайших, сочетается с фильтрами; вектор считается на лету, если фоновый анализ до семпла ещё не дошёл.
- Необязательно: поиск по описанию («dark punchy kick») — требует текстовый энкодер CLAP (127–500 МБ, только английский). Делать, только если категорий, тегов и поиска похожих окажется мало.
- Поиск дубликатов: точные (хеш) и акустические (отпечатки), с мастером объединения. **Точные готовы (2026-10-23):** кандидаты по отпечатку и размеру, файлы больше 128 КиБ подтверждаются полным хешем xxh3-128 в фоне (на реальной библиотеке 626 файлов за 0,1 с, отсеяно 2 ложных совпадения); 1 502 группы, 1 661 лишняя копия, 148 МБ. Раздел Duplicates в сайдбаре: правило выбора копии (короткий путь, старая, новая), закреплённые папки, ручной выбор. Лишние копии — в корзину (только подтверждённые) или скрыть из библиотеки (скан пропускает, список в настройках); избранное, теги и коллекции переходят на оставшуюся копию. Акустические дубликаты (тот же звук в другом файле или формате) — дальше.
- Опционально: 2D-карта библиотеки (UMAP по эмбеддингам).

### Этап 6 — Дальше
- Запись метаданных прямо в файлы (BWF/iXML, ID3).
- Синхронизация библиотеки между машинами (через папку в iCloud/Dropbox, без своего облака).
- Плагин для DAW (VST3/AU/CLAP через nih-plug) — браузер прямо внутри DAW.
- Windows и Linux.

## Риски

- **Лицензии**: GPL/AGPL-библиотеки (aubio, Essentia, Rubber Band) исключены — см. [dependencies.md](dependencies.md).
- **Веса моделей стем-сепарации**: Demucs — только для исследований, многие RoFormer-чекпоинты с неясным происхождением данных. Spleeter безопасен, но уступает по качеству. Нужна юр. проверка перед включением более сильных моделей.
- **Качество стемов** — главный параметр сравнения с Logic/FL; без сильной модели функция будет выглядеть слабее конкурентов.
- **Размер моделей**: аудио-энкодер CLAP — 34 МБ (int8), модели стемов — сотни МБ; скачивать по требованию.
- **Объём редактора** — легко разрастается до DAW; держать фокус на операциях над одним файлом.
- **Точность BPM/тональности** на one-shot'ах бессмысленна — показывать только для лупов.
- **Drag-out в разные DAW** ведёт себя по-разному — тестировать в Ableton, Logic, FL, Bitwig на раннем этапе.
- **Производительность скана** на сетевых и внешних дисках.
