# Fonicca — план

Десктопный менеджер семплов: «разобрал библиотеку → почистил → выгрузил в DAW или на железо» в одном приложении.

## Позиционирование

На рынке менеджеры (XO, Sononym, ADSR Sample Manager, Loopcloud, Splice) не редактируют файлы, а редакторы (Audacity, RX) не управляют библиотекой. Ставка Fonicca — на три пробела:

1. **Библиотека + встроенный аудиоредактор, пакетная обработка и стем-сепаратор** — обрезка, нарезка, фейды, нормализация, конвертация, разделение треков на стемы и сохранение фрагментов как семплов.
2. **Экспорт китов под железо** — Digitakt, SP-404, MPC, Polyend, M8 одной кнопкой.
3. **Локальный поиск похожих и поиск текстом** для любых звуков, офлайн, без подписки.

Плюс принципы: метаданные не заперты в проприетарной базе, быстрая работа на 100k+ файлов.

## Стек

| Слой | Выбор | Почему |
|---|---|---|
| Оболочка | Tauri 2 | Маленький бинарник, Rust для тяжёлого аудио, нативные диалоги и drag-out |
| UI | Vue 3 + Vite + TypeScript, Pinia, shadcn-vue, UnoCSS | Привычный стек |
| Данные | SQLite (rusqlite на стороне Rust), FTS5 для поиска | Один файл, быстро, полнотекстовый поиск из коробки |
| Декодирование | symphonia | WAV/AIFF/FLAC/MP3/OGG на чистом Rust |
| Запись / ресемплинг | hound, rubato | WAV-запись, качественный SRC |
| Воспроизведение | rodio / cpal (Rust) | Нативный вывод превью и редактора |
| Time-stretch для превью | signalsmith-stretch (MIT) | Rubber Band — GPL/коммерческая лицензия |
| Анализ (BPM, тональность) | stratum-dsp | Работает локально; дополнительные анализаторы остаются вариантами развития |

| Waveform и редактор | gl-waveform + собственный canvas/CSS, пики из Rust | Диапазонные запросы и кэш пиков |

## Этапы

### Этап 0 — Каркас
- Tauri + Vue проект, CI-сборка под macOS (потом Windows).
- Добавление папок-источников, рекурсивный скан, запись в SQLite.
- Список файлов с виртуальным скроллом, базовые метаданные (длительность, sample rate, битность, каналы).
- Превью по клику / стрелкам, waveform (пики считаются в Rust и кешируются).
- Drag-and-drop файла в DAW.

**Готово, когда:** библиотека на 50k файлов сканируется, листается без лагов, звук играет мгновенно.

**Статус (2026-10-23):** реализовано всё, кроме CI. Скан 20k WAV — 1,2 с, повторный — 0,1 с. Папки пересканируются инкрементально при запуске. Для WAV с кодеками, которые не открывает symphonia (Ogg-in-WAV, часть ADPCM), метаданные читаются из RIFF-заголовка, но воспроизведение и waveform для них пока не работают.

### Этап 1 — MVP-библиотека
- Теги, избранное, коллекции (виртуальные папки), рейтинг.
- Поиск: FTS по имени/пути/тегам + фильтры по метаданным.
- Инкрементальный пересканирование и слежение за папками (`notify`).
- Обработка переездов/переименований файлов без потери тегов (по хешу).
- Экспорт/импорт тегов в sidecar-файл (JSON) — защита от vendor lock-in.

**Это MVP** — уже можно отдавать первым пользователям.

**Статус (2026-10-23):** готовы полнотекстовый поиск FTS5 (по имени, папкам и тегам, по началу слова, без учёта диакритики), теги, избранное, множественное выделение и drag нескольких файлов. Готовы слежение за папками (notify, пересканирование через 0,8 с тишины) и сохранение тегов и избранного при переименовании, переносе между папками и повторном добавлении источника (по отпечатку содержимого, данные удалённых файлов хранятся 90 дней). Готовы коллекции (контекстное меню строки, раздел в боковой панели, членство переживает переносы файлов) и экспорт и импорт избранного, тегов и коллекций в JSON (слияние, поиск файла по пути, затем по отпечатку). Этап 1 закрыт.

**Сортировка (2026-10-26):** клики по названию и всем колонкам переключают возрастание/убывание. Названия учитывают числа и регистр, пустые метаданные остаются внизу. Сортировка выполняется в SQLite до пагинации, стемы остаются под исходником, выделение сохраняется; колонка и направление запоминаются.

### Этап 2 — Анализ
- Фоновая очередь анализа с прогрессом, не блокирующая UI.
- BPM, тональность, громкость (LUFS), определение one-shot / loop.
- Автокатегория (kick, snare, hat, bass, vocal, pad…): сначала по имени файла и папкам, для остальных — по аудио-энкодеру CLAP (сравнение с заранее посчитанными векторами категорий). Тональность по звуку — только для тональных категорий.
- Превью в темпе и тональности, заданных пользователем. **Готово (2026-10-23):** кнопка Sync в плеере (темп и тональность проекта хранятся в settings.json); лупы с известным BPM растягиваются к темпу проекта (с выбором половинного/двойного темпа, не более ×2), сэмплы с известной тональностью транспонируются к ней (кратчайший интервал, параллельные мажор/минор считаются одной тональностью); рендер signalsmith-stretch перед воспроизведением: 4-секундный луп — ~45 мс, файлы длиннее 60 с играют без изменений.

**Статус (2026-10-23):** готовы фоновая очередь (половина ядер, сначала видимые и выбранные семплы, пауза), громкость (пик, LUFS), one-shot / loop / long (по имени, длине, числу атак и огибающей) и BPM: из имени, для коротких лупов — по длине с выбором октавы детектором stratum-dsp (78% точно на 124 лупах без подсказки в имени), для длинных — детектором по 30-секундному окну. Вся библиотека (32k) анализируется за несколько минут.

**Категории (2026-10-23):** 17 категорий. Сначала по имени файла и папкам (82% реальной библиотеки, первое по положению ключевое слово, папки с общими барабанными словами не учитываются). Для остальных — по аудио-энкодеру CLAP (34 МБ, скачивается кнопкой, проверка SHA-256): 10 ближайших подписанных соседей из той же библиотеки, порог согласия 0,6 (~83% точности на половине неподписанных); при < 200 подписанных — заранее посчитанные текстовые прототипы. Тональность по звуку — только для тональных категорий (бас, синт, пэд, клавиши, гитара, струнные, духовые, вокал) и не для one-shot. Векторы сохраняются в базе для будущего поиска похожих; вся библиотека — около 27 минут в фоне.

### Этап 3 — Аудиоредактор и пакетная обработка
**Встроенный редактор** (двойной клик, клавиша E или пункт меню) открывается под таблицей, разворачивается на всю правую область; инструменты, не помещающиеся по ширине, доступны через «…». Отдельные окна остаются совместимыми с прежним способом запуска. **Основа готова (2026-10-23):** waveform с зумом и прокруткой, выделение, курсор, воспроизведение выделения с петлёй; crop, delete, silence, fade in/out (3 кривые), gain ±3 dB, normalize (−0.3 dB), reverse; бесконечный undo/redo (правки — список поверх исходника); сохранение: первая команда «Сохранить» создаёт WAV «<имя> — edited» рядом, переключает редактор на него и снимает отметку правок; следующие сохранения обновляют этот файл. «Сохранить как…» выбирает другой путь, «Сохранить выделение…» экспортирует фрагмент без переключения редактора, «Заменить оригинал…» требует явного подтверждения и доступно для WAV. При перезаписи существующего WAV сохраняется копия в папке backups. При закрытии с правками — «Сохранить / Не сохранять / Отмена». **Сетка и привязка (2026-10-24):** сетка тактов и долей по BPM сэмпла (поле BPM правится, 4/4, «первый такт от курсора», без BPM — сетка по времени), привязка курсора и выделения к сетке (магнит, S) и к нулям сведённого сигнала в пределах 10 мс (меню «Вид»); ⌥ при перетаскивании инвертирует обе. **Точки лупа (2026-10-24):** из выделения (⇧L), правка в общем списке (undo, сдвиг при crop/delete); читаются из `smpl`-чанка WAV при открытии и пишутся в него при сохранении (одна прямая петля, unity note C4); полоса на линейке, клик по ней выделяет луп. **Нарезка (2026-10-24):** редактируемые маркеры: каждый начинает регион до следующего; M или двойной клик по линейке ставит маркер, флажок перетаскивается (с привязкой к сетке и нулям), правый клик удаляет, клик по региону на линейке выделяет его, ⌥-клик пропускает (пропущенные затемнены и не сохраняются). Маркеры — правки в общем списке (undo, сдвиг при crop/delete/paste) и сохраняются в WAV как cue-точки (пропущенные с меткой «skip»). Расстановка автоматически — по сетке BPM (1/16–4 такта), по ударам (рост уровня высокочастотной составляющей, чувствительность 2–12 dB, минимальная длина, старт за 5 мс до удара) или по тишине (звучащие куски, паузы пропускаются) — заменяет маркеры в выделении или добавляется к ним. Отдельная кнопка «Сохранить регионы» пишет непропущенные регионы WAV в папку «<имя> slices» рядом с файлом и сразу добавляет в библиотеку. **Cut/copy/paste (2026-10-24):** буфер общий для всех окон редактора (можно копировать из одного файла в другой; каналы и частота приводятся к файлу, куда вставляют); вставка — одна правка в списке (вместо выделения или в позицию курсора), вставленное выделяется, петля сдвигается; ⌘X/⌘C/⌘V приходят через меню Edit как DOM-события. **Тон, длительность и LUFS (2026-10-24):** отдельные диалоги для выделения или всего файла: тон ±24 полутона независимо от длительности, растяжение 25–400%; обработанный звук хранится одной правкой, маркеры и точки лупа перемещаются пропорционально. Нормализация интегральной громкости с целью −36…−5 LUFS и потолком пиков отсчётов −12…0 dBFS; если цель недостижима без превышения потолка, усиление ограничивается и показывается достигнутая громкость (это не true-peak лимитер). Для LUFS нужно не менее 400 мс слышимого звука. Обработка идёт вне общей блокировки сессий; устаревший результат не применяется. **Удаление DC offset (2026-10-24):** вычитание среднего отдельно по каждому каналу в выделении или всём файле; кнопка на панели обработки и пункт контекстного меню, одна правка с undo/redo, длительность, маркеры и точки лупа сохраняются. **Спектрограмма (2026-10-24):** переключение «Волна / Спектрограмма» иконками в нижней панели рядом с настройками вида, общие масштаб, прокрутка, курсор, выделение, петли и маркеры; логарифмическая шкала от 20 Гц до частоты Найквиста, энергия −100…0 dBFS. FFT с окном Hann считается в фоне без удержания общей блокировки сессий, энергия стереоканалов усредняется без подавления противофазного звука. Частотный кеш ограничен 32 МиБ на открытый файл; при уменьшении масштаба берутся максимумы, чтобы не терять короткие транзиенты. Кеш сохраняется при изменении маркеров и точек лупа, сбрасывается после правок звука, undo и redo. Интерфейс запрашивает только видимый участок с запасом, устаревшие ответы отбрасываются.
- Waveform с зумом до сэмпла, выделение регионов, курсор, лупинг выделения при прослушивании.
- Операции: cut / copy / paste / delete / crop, тишина, fade in/out (с выбором кривой), gain, normalize (peak / LUFS), reverse, DC offset.
- Снап к zero-crossing, точки лупа (запись `smpl`-чанка в WAV для семплеров).
- Нарезка: по транзиентам, по сетке BPM, по тишине → экспорт слайсов как новых семплов в библиотеку.
- Pitch / time-stretch выделения (signalsmith-stretch).
- Вид спектрограммы.
- **Готово (2026-10-23): настраиваемая волна** (Settings → Waveform): пики / пики + RMS / столбики, линейная шкала или dB, каналы раздельно или смешанно, цвет по частотам (низ — красный, середина — зелёный, верх — синий); на глубоком зуме — кривая с точками отсчётов; ⌥-прокрутка — вертикальный зум; мини-карта всего файла над волной (видимый участок рамкой, перетаскивание, колесо — зум, двойной клик — показать всё). В плеере всё то же: волна строится из потокового обзора файла (пик, RMS, полосы по блокам, кэш последних 8 файлов в памяти); путь к файлу — внизу, сокращённый, клик открывает Finder.
- Неразрушающая модель: список правок (edit list) поверх исходника, многоуровневый undo/redo, рендер при сохранении — новый файл или замена с бэкапом.

**Пакетная обработка** над выделением в библиотеке. **Готово (2026-10-24):** пункт «Обработать…» в контекстном меню и палитре; шаги по порядку — обрезка тишины (порог, запас вокруг), смена каналов, удаление DC offset, нормализация пика, фейды (3 кривые), частота (rubato), нормализация LUFS, разрядность; переименование по шаблону (`{name}`, `{n}`, `{category}`, `{bpm}`, `{key}`, `{kind}`, пустые значения не оставляют лишних разделителей, предпросмотр имён); результат — копии WAV в выбранную папку или замена оригиналов (только WAV, без переименования, оригинал в backups; теги сохраняются, т. к. путь тот же). Обработка в фоне на всех ядрах с прогрессом и остановкой, папки сразу пересканируются; настройки и пресеты запоминаются. Нормализация — по пику или LUFS с потолком пиков отсчётов; в отчёте громкость до/после и файлы, где потолок ограничил достижение цели. Для LUFS нужны не менее 400 мс слышимого звука: неподходящие файлы пропускаются с ошибкой без перезаписи. Старые пресеты сохраняют режим нормализации по пику. Не сделано: другие форматы на выходе, произвольный порядок шагов.
- Обрезка тишины, нормализация, фейды, конвертация формата/SR/битности, моно↔стерео.
- Переименование по шаблону (`{category}_{bpm}_{key}_{n}`).
- Пресеты цепочек операций.

### Этап 3.5 — Стем-сепаратор

**Первая версия (2026-10-25):** Spleeter 4-stems через ONNX Runtime CPU, загрузка модели по требованию (78,9 МБ, закреплённая revision и SHA-256), прогресс и отмена. Вокал / барабаны / бас / остальное пишутся стерео WAV 44,1 кГц / 32-bit float, автоматически добавляются в библиотеку с тегами `stem:*`; каждый стем доступен в обычном редакторе. Исходник сохраняется; незавершённые результаты удаляются при отмене. Одна активная задача, до 10 минут моно/стерео. Скорость и восстановление суммы проверены на официальном тестовом аудио; оценка качества на слух, CoreML, 2/5 стемов и очередь нескольких заданий — дальше. [Модель, лицензия и замеры](research/stem-separation.md).
- Разделение трека на стемы: 2 (вокал / минус), 4 (вокал, барабаны, бас, остальное), 5 (+ пианино).
- Инференс локально через ONNX Runtime, на macOS — CoreML (Apple Silicon); фоновая очередь с прогрессом и отменой.
- **Готово (2026-10-25):** SCNet-large — сбалансированный режим (45,1 МБ), Spleeter — быстрый режим. Выбор сохраняется, доступность и занимаемое место видны в настройках. На трёх фрагментах MUSDB18 test SCNet-large улучшил SI-SDR на всех 12 стемах; CPU-запуск на M1 Pro проверен, native/reference SNR 128–130 дБ. CoreML и отдельная вокальная модель RoFormer — дальше. [Сравнение](research/scnet-comparison.md).
- **Проверен и удалён (2026-10-25):** HTDemucs FT исключён из приложения по запросу; скачанные веса удалены. Результаты локального сравнения сохранены. Сверен с независимым запуском на NumPy/ONNX; средний результат на трёх тестовых фрагментах уступил SCNet-large, поэтому default сохранён. У исходных весов ограничение на научные цели. [Результаты](research/htdemucs-ft-comparison.md).
- **Проверен (2026-10-25):** SCNet XL IHF, исходные веса 214 МБ, три тех же тестовых фрагмента. Средний SI-SDR немного выше Large (+0,22…0,73 дБ по стемам), но результат зависит от песни; CPU 35–42 с на 6,8 с в PyTorch. Отдельная страница сравнения готова. Добавлен FP32 ONNX-вариант (221,5 МБ), режим качества по умолчанию для новых настроек; Large остаётся сбалансированным режимом. Нормализация выключена согласно конфигурации XL. [Отчёт](research/scnet-xl-ihf-comparison.md), [интеграция и проверка совпадения](research/scnet-xl-ihf-integration.md).
- **Готово (2026-10-25):** исходник с меткой «Стемы · N» раскрывает вложенные дорожки в библиотеке. Связи хранятся в БД, новые WAV сохраняются рядом с исходником или в выбранной в настройках папке. ## Бэклог: карта звуков — отложено

Решение от 2026-10-28: убрать экспериментальную карту из приложения вместе с переключателем вида, командой расчёта и зависимостями. Вернуться после основных задач библиотеки и редактора. Поиск похожих звуков и существующий анализ CLAP остаются отдельными функциями.

### Последний согласованный вариант

**Цветная 2D-гистограмма плотности**: карта разбивается на прямоугольные ячейки; одна ячейка объединяет попавшие в неё семплы. [Интерактивный пример](design/library-density-grid.html) использует демонстрационные данные и показывает только концепцию, а не готовый анализ библиотеки.

- Каждый тип звука получает свой постоянный цвет: Kick, Snare, Hi-hat, Bass, Vocal, FX и остальные. Цвет типа сохраняется при переключении режимов.
- Цвет ячейки соответствует преобладающему типу; яркость отражает количество семплов, а не громкость или качество звука. Для смешанной ячейки доступен полный состав по типам.
- Режимы расположения: **Тип** — отдельные области по категориям; **Звучание** — близость тембра по эмбеддингам; **Темп** — BPM; **Ритм** — сходство рисунка ударов и грува.
- Переключение меняет расположение одних и тех же звуков с плавным переходом. Выбранный семпл, поиск и фильтры сохраняются.
- При выборе ячейки показываются количество звуков и состав по типам; далее — переход к её семплам и прослушиванию. При увеличении масштаба возможна детализация до отдельных звуков.
- Режимы «Тип», «Звучание» и «Темп» могут опираться на существующие данные. Для режима «Ритм» нужен отдельный анализ атак и временной структуры: BPM сам по себе не описывает грув. Пропущенные значения и звуки без анализа нужно учитывать явно, не присваивать им вымышленные координаты.
- Перед внедрением проверить читаемость плотности и категорий в светлой/тёмной теме, поведение на больших библиотеках, скорость переключений и локальное кеширование. Стек пока не закреплять.

Референсы: [2D histogram / D3 Graph Gallery](https://d3-graph-gallery.com/graph/density2d_histogram2d.html), [Infinite Drum Machine](https://experiments.withgoogle.com/ai/drum-machine/view/), [Atlas](https://algonaut.audio/).


### Память редактора (2026-10-28)

Фиксированный предел 20 минут заменён бюджетом декодированного PCM: 1/6 доступной RAM, не более 2 ГиБ на один PCM-буфер; если сведения о RAM недоступны — 256 МиБ. Остаток оставляется под оригинал, рабочую копию, воспроизведение, перерисовку undo и волны. Проверка идёт во время декодирования до расширения буфера; слишком большой файл отклоняется, а не обрезается. При увеличении длительности и вставке проверяются итоговый размер и дополнительная память. Загрузка выполняется вне асинхронного обработчика команд.

Это по-прежнему редактор с полной загрузкой PCM в RAM: бюджет не является гарантией пикового расхода, особенно при длинной истории обработки и нескольких окнах. Дисковая/блочная обработка очень длинных записей остаётся отдельной задачей.


### Общие аудиоданные и блочное редактирование (2026-10-29)

- Открытие сохраняет один декодированный буфер. Плеер и фоновая спектрограмма читают неизменяемые снимки с общей памятью; старт, перемотка и изменение диапазона не копируют PCM.
- Редактор хранит список диапазонов общих буферов. Обрезка/удаление меняют ссылки; вставка использует готовые данные; эффекты создают только изменённые участки блоками до 16 384 фреймов. Остальная часть файла разделяется между версиями.
- Undo/redo восстанавливают снимки аудио, маркеров и петли, без копирования оригинала и повторного применения всей цепочки. Сохранение и экспорт выделения читают диапазоны без сборки всего файла в новый буфер.
- Проверяется дополнительная память при эффектах. Длинная история полных обработок может удерживать много данных; первоначальное декодирование всё ещё целиком в RAM. Дисковая подкачка и выгрузка истории — отдельный следующий этап, не часть текущей реализации.


### Дисковое хранение длинных записей (2026-10-29)

- Исходник декодируется потоком. До 32 МиБ PCM (или меньшего текущего бюджета RAM) хранится в памяти; при превышении порога уже полученные данные и следующие порции уходят в приватный безымянный временный файл. Полный PCM-буфер перед этим не создаётся.
- Файл отображается только для чтения через `memmap2`; страницы подгружает и освобождает ОС. Это не жёсткая гарантия RSS: проигрывание, волна и анализ могут прогревать файловый кеш. Файл остаётся жив, пока нужен плееру, спектрограмме или undo; последний снимок освобождает отображение и дескриптор временного файла.
- Усиление, фейды, нормализация, удаление DC и reverse считают результат блоками; большие результаты также уходят на диск. Операция публикует новый снимок только после успешного окончания записи. Ошибки записи и некорректные вставки сохраняют предыдущий звук, петли, маркеры и историю.
- Общий размер длинного исходника больше не ограничен бюджетом одного RAM-буфера или 2 ГиБ. Ограничениями остаются адресное пространство процесса, доступное место для временного PCM и время декодирования.
- Time-stretch/pitch, LUFS-обработка и буфер обмена пока требуют материализации выбранного диапазона в RAM; для них оставлены предварительные проверки памяти. Дисковые сброс/восстановление истории и упреждающая загрузка страниц для гарантированной низкой задержки — дальнейшие задачи.

### Отладочный монитор редактора

Кнопка внизу левой панели, над настройками, рядом с загрузкой звуковой модели. Плавающее окно можно перемещать за заголовок. Замеры раз в секунду, только пока монитор открыт и окно видно; есть пауза и сброс отсчёта. Для сравнения: открыть монитор, сбросить отсчёт, открыть длинный трек, выполнить короткую и полную обработку, отменить/повторить, закрыть трек.

- RSS и CPU относятся к процессу Rust, без отдельных процессов WebView; 100% CPU = одно ядро. График и пик показывают только полученные замеры, краткий скачок между ними может быть пропущен.
- Аудио в RAM и на диске — уникальные хранилища текущей сессии вместе с историей и сохранёнными операциями. Общие данные считаются один раз. Это не расход всей программы: временные рабочие буферы обработки, буфер обмена и снимки, удерживаемые плеером после изменения сессии, сюда не входят.
- Объём дискового PCM — размер отображённых временных файлов, не объём резидентных страниц; их страницы могут входить в RSS. Кеш отдельно показывает массивы пиков и спектрограммы, без служебных структур.
- Открытие — декодирование и подготовка сессии; время последнего запроса волны — работа backend, включая построение пирамиды пиков, без IPC и отрисовки.
- Пока обработка держит сессию, её счётчики временно недоступны; RSS/CPU продолжают обновляться. В браузерных моках данные демонстрационные и явно подписаны.

### Быстрые изменения и отмена в редакторе

Кеш пиков теперь принадлежит неизменяемому аудиохранилищу и разделяется его фрагментами и снимками истории. Удаление и обрезка меняют расположение фрагментов; короткие эффекты строят пики только для нового звука. Отмена/повтор используют готовые пики. Смена маркеров и loop points не сбрасывает их. В мониторе кеш считается один раз по всем снимкам сессии.

Запрос волны и простые эффекты выполняются в рабочих потоках на снимке аудио, без удержания блокировки сессии. Результат эффекта записывается только при совпадении версии исходника. Копирование при вырезании тоже вынесено из потока интерфейса; ошибка копирования не удаляет выбранный звук. Пока изменение выполняется, повторное действие не запускает второй запрос.

Для границ столбцов волны min/max/RMS считаются точно по выбранным семплам: удалённые пики не попадают в соседние фрагменты. Частотная окраска использует приближение энергии для неполного базового блока (до 64 кадров); это только визуализация, PCM не изменяется.

Нативный контрольный замер (`benchmark_edit_wave_latency`, ignored, debug opt-level 1): стерео 44,1 кГц, 3 минуты, 1600 столбцов, после первой загрузки кеша. Затухание последней секунды вместе с обновлением волны: 144,6 → 3,4 мс; удаление секунды: 136,5 → 2,1 мс; отмена: 138,2 → 1,6 мс. Первый расчёт пиков по-прежнему требует прохода по исходнику (~150 мс в этом тесте); обработка всего длинного трека требует чтения и записи всего выбранного диапазона.
