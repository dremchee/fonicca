# HTDemucs FT, SCNet-large и Spleeter — 2026-10-25

На тех же трёх тестовых фрагментах SCNet-large сохранил лучший средний SI-SDR
по каждому стему. HTDemucs FT немного лучше выделил бас на Cristina Vane и Louis
Cressy Band, но проиграл на Secretariat. Поэтому HTDemucs FT добавлен как
альтернатива, а не как безусловное улучшение или новый режим по умолчанию.

| Средний SI-SDR, дБ | Spleeter | SCNet-large | HTDemucs FT |
|---|---:|---:|---:|
| Вокал | 8,03 | 13,10 | 10,29 |
| Ударные | 5,40 | 10,24 | 8,59 |
| Бас | 0,74 | 6,41 | 6,07 |
| Остальное | 3,47 | 7,25 | 5,33 |

Материал и метод SI-SDR описаны в [предыдущем сравнении](scnet-comparison.md).
Три официальных превью MUSDB18 test, по 6,8034467 с; те же mix и отдельные
эталоны, то же стерео-преобразование в вектор и удаление среднего. Выборки мало
для общего рейтинга, это не BSSEval SDR и не обещание превосходства на любой музыке.
С VirtualDJ модель не сравнивалась.

[Сырые измерения трёх моделей](htdemucs-ft-comparison.json).
Полный HTDemucs FT FP32 без случайных сдвигов; независимый Python/NumPy + ONNX
Runtime 1.31.0 запуск с описанной в исследовании upstream-схемой окон.
Нативная реализация на Rust/ONNX Runtime сверена на Cristina Vane: SNR
121–129 дБ для каждого стема, т.е. практически совпадает с NumPy-эталоном.

## Производительность

M1 Pro, 16 ГБ; CPU, до четырёх потоков. Четыре специалиста загружаются
последовательно, один используется для всех окон всех трёх тестовых песен.
В Python суммарная загрузка четырёх сессий заняла 15,92 с; инференс на фрагмент:
54,46 / 31,21 / 28,37 с. Во время запуска шла компиляция, особенно на первом
фрагменте; эти времена не являются чистым сравнением скорости моделей.

Первый нативный замер: 6,80 с за 42,53 с, максимальный RSS 5,04 ГБ,
macOS peak memory footprint 9,23 ГБ. Это показало необходимость отдельно
ограничить удержание временной памяти CPU execution provider.
В итоговом варианте его arena allocator выключен: тот же нативный тест дал
35,22 с, RSS 4,22 ГБ и peak memory footprint 7,43 ГБ. Совпадение с эталоном
сохранилось (SNR 121–129 дБ); разница времени не является чистым сравнением,
так как фоновые нагрузки отличались. Модель всё равно требует заметно больше
памяти, чем размер файлов весов.

Полная запись 11,97 с успешно экспортирована в четыре WAV за 46,37 с;
отдельно проверено, что отмена после первого обработанного окна удаляет
незавершённую папку и сохраняет исходный файл побайтно.

## Проверки

Из папки `src-tauri`:

```sh
cargo test --lib
DEMUCS_MODELS=/path/to/demucs-pack STEM_AUDIO=/path/to/mix.wav \
  DEMUCS_REFERENCE=/path/to/numpy-stems \
  cargo test --lib stems::demucs::tests::real_model_inference -- --ignored --exact --nocapture
DEMUCS_MODELS=/path/to/demucs-pack STEM_AUDIO=/path/to/12s.wav \
  cargo test --lib stems::tests::demucs_file_export_keeps_original_and_cleans_cancelled_work -- --ignored --exact --nocapture
DEMUCS_MODELS=/path/to/demucs-pack \
  cargo test --lib stems::models::tests::downloaded_demucs_manifest_and_notices_are_verified -- --ignored --exact --nocapture
```

Тензорные формы, длина, порядок, конечность отсчётов и совпадение с эталоном
проверены на реальных весах. Обычные тесты не скачивают гигабайтный комплект.
Веса и музыкальные записи не включены в Git. Локальная страница прослушивания
обновлена по прежнему адресу `http://127.0.0.1:8766/comparison.html`, файлы лежат
в `~/.codex/artifacts/fonicca-stems-2026-10-25/`.

У весов Demucs есть ограничение на научное использование от автора;
подробности — в [исследовании моделей](stem-separation.md) и NOTICE.
